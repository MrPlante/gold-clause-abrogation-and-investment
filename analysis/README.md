# analysis/ — everything that produces the numbers in the paper

Replicates all manuscript tables and figures from
`data/processed/firm_year_panel.dta` (built by `pipeline/`; the original
Stata pipeline is in git history at `d54b0c3:code/legacy`). Generated tables
and figures are written DIRECTLY into `manuscript/tables/` and
`manuscript/figures/`.

**The naming invariant:** every file that corresponds to a manuscript object
carries the manuscript's current label, end to end. `--stage table4` runs
`tables/body/t04_investment.py`, which writes
`manuscript/tables/body/table4_investment.tex` — manuscript Table 4. Same
for the appendix: `--stage ia19` → `tables/appendix/ia19_controls_indyear.py`
→ `ia19_controls_indyear.tex` — Table IA.19. Manuscript Table 1 and Table
IA.20 come from the `eventstudy` stage. If the manuscript renumbers between
rounds, rename the files with it; the label→file mapping must never need a
lookup table again.

**Division of labor:** Python does the plumbing (specification, data
handling, LaTeX rendering, validation against the manuscript); **Stata's
`reghdfe` does the variance estimation** — every standard error the paper
reports comes from an actual `reghdfe` run (`USE_STATA_VCOV=auto`, via
`stata/reghdfe_vcov.do`). This is deliberate: with 15 year clusters and 16+
regressors the two-way clustered vcov is rank-deficient by construction and
every package repairs it with its own eigenvalue surgery, so SEs are
convention-dependent in the 3rd decimal (DISCREPANCIES.md D-019). The paper
standardizes on reghdfe's convention — the one referees know. A pure Python
run (`USE_STATA_VCOV=0`, CGM fix) reproduces every coefficient exactly and
all SEs within ~5%.

## Layout

```
analysis/
├── run.py              # CLI: --stage table2..table8 | ia1..ia19 | figures |
│                       #      eventstudy | compare | all   (see --help)
├── tables/
│   ├── body/           # t02..t08 -> manuscript Tables 2-8
│   ├── appendix/       # ia01..ia19 -> Tables IA.1-IA.19
│   ├── models/         # per-topic computations, shared across body/IA tables
│   └── render/         # per-topic LaTeX emitters (regression_table.py is the
│                       #   shared regression-table renderer)
├── eventstudy/         # Table 1, Figs 3-5, IA.2/IA.3, Table IA.20
│   └── pipeline.py     #   production event-study pipeline (fully offline:
│                       #   reads data/raw/crsp_daily.dta)
├── figures/            # Figures 1-2, 6, 7 (+ source-data/ transcriptions)
├── stata/              # reghdfe vcov bridge + IA.19 do-file + runner
├── lib/                # regressions, vcov, latex, validation
├── tests/              # byte-identity guard + per-table coefficient tests
└── compare/            # Stata-vs-Python regression diff harness (output/ is
                        #   gitignored, regenerated by every run)
```

A table's code shares one stem across layers: `ia15_dividend_additional.py`
(builder) → `models/dividend_additional.py` → `render/dividend_additional.py`.

## Running

```bash
.venv/bin/python analysis/run.py --stage table4     # one table
.venv/bin/python analysis/run.py --stage all        # everything
```

**The replication statement is unconditional** (since the D-022 final
addendum): from `data/raw/` + `data/processed/`, `pipeline/run.py` followed
by `analysis/run.py --stage all` reproduces every table and figure in the
manuscript exactly — no env vars, no skipped stages. `run.py`'s `FROZEN`
set (empty) remains as the guard mechanism: if a builder ever stops
reproducing its table, add its stage there and log it in DISCREPANCIES.md.
The Table 7 / IA.17 specs segfault the in-process Stata vcov bridge;
attach_cluster_vcov falls back to the CGM fix automatically for exactly
those regressions (printed as a [vcov] note during the run).

### Event study (Table 1, Figures 3–5, IA.2, IA.3, Table IA.20)

```bash
.venv/bin/python analysis/run.py --stage eventstudy
```

Builds the four daily portfolio return series (VW market, equal-weighted
d>0 / d=0, and d-weighted) from `data/raw/crsp_daily.dta` (the local dump of
`gold_claude.crsp`; see `data/README.md`) plus the firm-year panel. Fully
offline — no researchdb access, no Kerberos. Part of `--stage all`.

### IA.19: the one Stata-produced table

Table IA.19's coefficients and SEs come from
`stata/ia19_controls_indyear.do` (run:
`stata-mp -b do analysis/stata/ia19_controls_indyear.do` from the repo
root), which writes `output/tables/ia19_controls_indyear.csv`;
`--stage ia19` renders that CSV to LaTeX. Deliberate: the portfolio-decile +
industry×year specs crash the in-process Stata vcov bridge, and pure-Python
CGM SEs are close but not identical to reghdfe. The CSV is versioned, so
`--stage ia19` (and `all`) work without Stata; rerun the do-file only if the
data changes.

### Stata vs Python comparison

```bash
.venv/bin/python analysis/run.py --stage compare
```

Runs the same reghdfe specifications in Stata and in the Python stack, then
diffs coefficients: 221/221 matched cells agree within 1e-3; SEs match when
Python uses the reghdfe vcov. Requires Stata (`STATA_BIN`, default
`/usr/local/stata/stata-mp`) and packages `require`, `ftools`, `reghdfe`,
`winsor2` (auto-installed on first run). Outputs land in the gitignored
`compare/output/`; details in `compare/README.md`.

## Validation and tests

Three layers, strongest first:

1. **Byte-identity guard** — the replication statement made executable.
   For each stage it snapshots `manuscript/tables/` + `manuscript/figures/`,
   runs the stage, fails if any byte changed, and restores the originals
   either way (the working tree is never left dirty):

   ```bash
   .venv/bin/python analysis/tests/check_byte_identity.py              # all stages (slow)
   .venv/bin/python analysis/tests/check_byte_identity.py table4 ia15  # a subset
   ```

   Figure PDFs are covered too: `run.py` pins `SOURCE_DATE_EPOCH` so
   matplotlib output is byte-deterministic. If a stage fails here, either
   the builder broke (fix it or add the stage to `run.py`'s `FROZEN` set
   and log it in DISCREPANCIES.md) or the change is deliberate (rerun the
   stage via `run.py` and commit the new table with the source change).

2. **Builder self-validation** — every builder checks its key numbers
   against the manuscript tex it just wrote (tolerance
   `config.COEF_TOLERANCE` = 0.001) and fails loudly on drift.

3. **Per-table coefficient tests** — standalone re-derivations for
   Tables 2-8 and IA.1-IA.6:

   ```bash
   for t in analysis/tests/test_*.py; do .venv/bin/python "$t" || echo "FAIL $t"; done
   ```

`DISCREPANCIES.md` (repo root) is the running log of every known difference
vs the published manuscript and its resolution — read it before trusting or
"fixing" any mismatch.
